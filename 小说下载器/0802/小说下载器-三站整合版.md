## 本次更新内容

### 核心改动：验证码处理机制重构

#### 1. `getHtml` 方法 - 验证码检测立即拒绝

**改动前**：
- 检测到验证码后，调用 `handleVerify` 方法
- 打开新标签页让用户手动验证
- 显示验证按钮UI，等待用户确认

**改动后**：
- 检测到验证码时，立即 `reject(new Error('VERIFY_DETECTED'))`
- 不再弹出任何验证UI
- 直接返回错误，由调用方处理

```javascript
if (this.detectVerify(html)) {
    this.currentSite = oldSite;
    reject(new Error('VERIFY_DETECTED'));
    return;
}
```

---

#### 2. `downloadChapter` 方法 - 捕获验证错误并保存进度

**改动前**：
- 遇到验证码错误会重试
- 重试失败后标记为下载失败

**改动后**：
- 专门捕获 `VERIFY_DETECTED` 错误
- 保存当前下载进度到 GM_setValue
- 设置 `this.config.cancel = true` 停止整个下载流程
- 在 resultMap 中记录该章节因验证码中断

```javascript
if (e.message === 'VERIFY_DETECTED') {
    console.warn(`⚠️ 检测到验证码，停止下载: ${task.title}`);
    this.config.resultMap[task.globalIndex] = `${task.title}\n\n遇到验证码，下载中断\n\n`;
    this.saveProgress();
    this.config.cancel = true;
    return;
}
```

---

#### 3. `autoScanAndShowDownload` 方法 - 显示恢复进度提示

**改动前**：
- 扫描完成后直接开始下载
- 无进度提示

**改动后**：
- 检测是否有已保存的下载进度
- 如果有进度，在状态和通知中显示跳过提示
- 用户可以看到已下载章节数和自动跳过提示

```javascript
const hasProgress = this.config.completed > 0 && Object.keys(this.config.resultMap).length > 0;
const progressHint = hasProgress ? ` (已下载${this.config.completed}章，将自动跳过)` : '';
this.showNotice(`扫描成功，共 ${this.config.chapterList.length} 章${progressHint}，开始下载`);
```

---

#### 4. `startDownload` 方法 - 跳过已完成章节

**改动前**：
- 每次下载都从第一章开始
- 清空所有进度数据

**改动后**：
- 检测是否有已保存的进度
- 如果有进度，使用 `tasks.slice(completedCount)` 跳过已完成章节
- 保留已有的 resultMap，不清空
- 显示恢复下载通知

```javascript
const hasProgress = this.config.completed > 0 && Object.keys(this.config.resultMap).length > 0;
if (hasProgress) {
    const completedCount = this.config.completed;
    const remainingCount = tasks.length - completedCount;
    console.log(`📂 检测到下载进度: 已完成${completedCount}章，剩余${remainingCount}章`);
    this.showNotice(`恢复下载: 已完成${completedCount}章，从第${completedCount + 1}章继续`);
    tasks = tasks.slice(completedCount);
}
```

## 工作流程

### 下载流程（遇到验证码时）

```
开始下载
  ↓
逐章下载
  ↓
getHtml 请求章节内容
  ↓
检测验证码关键词
  ↓
发现验证码 → reject('VERIFY_DETECTED')
  ↓
downloadChapter 捕获错误
  ↓
保存当前进度 (GM_setValue)
  ↓
设置 cancel = true 停止下载
  ↓
显示通知：遇到验证码，下载中断
```

### 恢复下载流程

```
用户再次点击扫描/下载
  ↓
autoScanAndShowDownload 检测进度
  ↓
显示提示：已下载X章，将自动跳过
  ↓
startDownload 检查 hasProgress
  ↓
跳过已完成章节 (tasks.slice)
  ↓
从断点继续下载
  ↓
全部完成后清理进度
```

## 技术细节

### 进度存储
- 使用 `GM_setValue` / `GM_getValue` 存储进度
- 存储键：`novelDownloader_progress`
- 存储内容：
  ```json
  {
    "completed": 已下载章节数,
    "resultMap": {
      "章节索引": "章节内容"
    }
  }
  ```

### 验证码检测
- 仅对站点C（hasVerify: true）生效
- 检测关键词：`['验证', 'verify', 'captcha', 'check', '安全', '人机']`
- 使用 `toLowerCase()` 进行不区分大小写的匹配

### 错误处理
- `VERIFY_DETECTED` 是自定义错误类型
- 不会触发重试机制
- 直接中断下载并保存进度

---

## 注意事项

1. **进度持久化**：进度保存在 Tampermonkey 的存储中，清除脚本数据会丢失进度
2. **验证码处理**：遇到验证码后需要手动完成验证，然后重新触发下载
3. **章节顺序**：恢复下载严格按照章节顺序跳过，确保内容完整性
4. **站点限制**：仅站点C有验证码检测，站点A和B不受影响
