# 小说下载器-合并版 使用说明

> 融合"三站整合版"与"自动爬取版"，统一数据结构与断点续传机制。
> 版本：v2.3 ｜ 文件：[小说下载器-合并版.user.js](./小说下载器-合并版.user.js)

---

## 一、功能概览

| 特性 | 说明 |
|---|---|
| **双模式自动识别** | 目录页 → 批量模式；正文页 → 链路模式 |
| **三站点适配** | A/B/C 三站独立选择器与提取器，通用兜底选择器覆盖未知站点 |
| **断点续传** | 基于 GM_setValue 持久化，刷新/关闭后可从断点继续 |
| **验证码处理** | C 站命中验证码立即保存、记录暂停章、完成验证后可续传 |
| **章节排序** | url→globalIndex Map 映射，确保导出顺序与目录一致 |
| **手机浏览器适配** | 响应式 UI、面板可拖动、可折叠、复选框可见 |
| **倒计时提示** | 等待/暂停时状态栏每秒刷新（60→59→...→0） |
| **差异化限速** | C 站严格反爬保留原延迟；A/B 站放宽 3 倍速度 |
| **无弹窗打扰** | 所有提示在状态栏显示，不打断操作 |
| **章节标题正则识别** | INDEX_REG 覆盖中英文小说常见命名，未知站点目录也能识别 |
| **最大文本块算法** | auto 提取器兜底用最大文本块算法，提升内容提取准确率 |
| **章节内分页嗅探** | 自动拼接"下一页"分页内容，避免漏抓 |
| **指数退避重试** | 1s→2s→4s→8s 指数退避 + 随机抖动，降低反爬识别风险 |

## 二、安装

1. 安装 Tampermonkey（桌面）或 Kiwi Browser + Tampermonkey（Android）或 Userscripts（iOS）
2. 创建新脚本，粘贴 `小说下载器-合并版.user.js` 全部内容
3. 保存（Ctrl+S）

## 三、使用流程

### 场景 A：目录页批量下载

1. 打开小说目录页
2. 面板自动显示："已检测到目录页（批量模式）"
3. 点击 **🔍 扫描** → 章节列表填充
4. 勾选目标章节（或用范围选择：起-止）
5. 点击 **▶ 开始** → 并发下载
6. 完成后状态栏显示"✅ 批量下载完成"
7. 点击 **💾 保存** → 导出 TXT

### 场景 B：正文页链式爬取

1. 打开小说第一章正文页
2. 面板自动显示："已检测到正文页（链路模式）"
3. 点击 **▶ 开始** → 自动抓取当前章 → 跳转下一章 → 循环
4. 完成后点击 **💾 保存**

### 场景 C：断点续传

1. 下载中断（关闭页面/暂停/验证码触发）
2. 重新打开同一页面
3. 面板显示："已恢复进度: N 章，点击开始继续"
4. 点击 **▶ 开始** → 自动从断点继续

### 场景 D：C 站验证码

1. 爬取中命中验证码
2. 脚本立即保存进度、记录待验证章
3. 状态栏提示"⚠️ 第N章触发验证码，已保存 N 章"
4. 在浏览器手动完成验证
5. 点击 **▶ 开始** → 从待验证章继续

## 五、差异化限速

| 站点 | 批量并发 | 批量间隔 | 链路间隔 | 分批暂停 |
|---|---|---|---|---|
| **C 站**（hasVerify）| 3 | 1000ms | 2500ms | 每 10 章暂停 30 秒 |
| **A/B 站** | 6（上限 8）| ~333ms | ~833ms | 无 |

> 判定依据：`site.hasVerify`（仅 C 站为 true）
> A/B 站放宽 3 倍速度，C 站保留原反爬策略

## 六、倒计时显示

所有等待场景状态栏每秒刷新：

- 每分钟限制：`达到每分钟限制，等待 60秒` → `59秒` → ... → `0秒`
- C 站分批暂停：`C站限制，暂停 30秒` → `29秒` → ... → `0秒`
- 请求失败重试：`请求失败: xxx，重试 5秒` → `4秒` → ... → `0秒`

倒计时过程中点 **⏹ 停止** 可立即中断。

## 七、章节排序机制

### 数据结构

```javascript
// 扫描时记录的目录顺序
config.chapterList = [
    { title, url, globalIndex: 0 },
    { title, url, globalIndex: 1 },
    ...
];

// 下载完成的章节数组（顺序可能错乱）
config.chapters = [
    { title, content, url, globalIndex, timestamp, status, ... },
    ...
];
```

### 排序策略

`getSortedChapters()` 优先级：

1. **url → globalIndex Map 映射**（首选）
   - 数据源：`config.chapterList`
   - 覆盖批量模式、续传混合场景
2. **chapter.globalIndex 字段**（回退）
   - chapter 自带的原始顺序字段
3. **timestamp**（兜底）
   - 链路模式按爬取时间排序

### 排序应用位置

- UI 章节列表显示（`updateChapterList`）
- TXT 导出（`saveFile`）

## 九、正文页识别（手机端适配）

### 判定逻辑

1. **优先**：命中站点配置的 `contentSelectors` 且文本长度 ≥ `minTxtLength`
2. **兜底 1**：扫描 `[class*="content"]`、`[id*="chapter"]`、`article`、`main` 等疑似容器，文本 ≥ 300 字符
3. **不强制要求 nextUrl**：运行时再找下一章链接

### findNextUrl 增强

支持多种下一章元素：

- **标准 `<a href>`**
- **button / div 的 `data-href`、`data-url`、`data-next`**
- **`onclick` 中的 `location.href=`、`window.open()`、`location.replace()`**
- **手机端选择器**：`.pt-next`、`#btnNext`、`.m-nav a:last-child`、`a[rel="next"]`
- **简写文本**：下章、下页、下节、Next、›、»、▷

## 十一、常见问题

### Q: 面板样式泄漏到页面上？
A: 已修复。`:host, * { all: initial; }` 会重置 `<style>` 标签的 `display`，添加 `style { display: none !important; }` 解决。

### Q: 复选框看不见？
A: 已修复。`all: initial` 重置了 `appearance`，添加 `appearance: auto; -webkit-appearance: auto;` 恢复原生外观。

### Q: 章节顺序错乱？
A: 已修复。用 `url → globalIndex` Map 映射排序，兼容并发下载和续传场景。

### Q: 手机端面板遮挡内容？
A: 点击标题栏可折叠为 42px 高的条状，或拖动到屏幕角落。

### Q: 完成后无法下载下一本？
A: 完成后已自动清空存储，刷新页面即可。

### Q: 未知站点目录页识别不到？
A: v2.3 新增 INDEX_REG 正则兜底，遍历页面所有 `<a>` 匹配章节标题正则，覆盖"第一章/序章/Chapter 5/123章"等命名。若仍识别不到，可用菜单"🔍 重新检测模式"或手动输入章节 CSS 选择器。

### Q: 正文内容抓不全/抓到导航栏？
A: v2.3 的 auto 提取器新增最大文本块算法兜底，遍历 `span,div,article,p,td,pre` 取字符数最多的元素作为正文容器，并自动跳过 footer/nav/ad 等干扰区域。

## 十二、通用规则增强（v2.3 新增）

参考业界标杆"怠惰小说下载器（DownloadAllContent）"集成 4 项通用能力：

### 1. 章节标题正则 INDEX_REG

```
匹配范围：
- 中文：第一章/第3回/序章/楔子/番外/分卷/前言/后记/结语/尾声/最终话
- 英文：PART 2/Chapter 5/Prologue
- 数字：1. / 1、 / 1： / 1） / 01章
```

**应用位置**：`scanByIndexReg()` 方法
- 在站点配置选择器和通用兜底选择器都未命中时触发
- 遍历页面所有 `<a>`，匹配正则识别章节链接
- 同时支持 URL 含 `chapter-N` 模式的识别

### 2. 最大文本块算法

**应用位置**：`extractAuto()` → `findLargestTextBlock()`

三级回退策略：
1. `<p>` 标签聚合（≥50 字符）
2. **最大文本块算法**：遍历候选元素，取直接子文本字符数最多者
   - 跳过 `class*="footer|header|nav|sidebar|comment|ad|menu"`
   - 排除"5+ 子元素匹配章节标题正则"的容器（避免误抓目录）
3. 整个容器文本（兜底）

### 3. 章节内分页嗅探

**应用位置**：`downloadOne()` → `findInnerNextPage()`

识别"下一页/下一张/next page/次のページ"，自动抓取并拼接到当前章内容：
- 最多拼接 10 页
- `visitedUrls` Set 防止循环
- 区别于 `findNextUrl`（找"下一章"作为新章节）

### 4. 指数退避重试

**应用位置**：`getHtmlWithRetry()`

| 重试次数 | 等待时间 |
|---|---|
| 第 1 次失败 | 1s + 0~500ms 抖动 |
| 第 2 次 | 2s + 抖动 |
| 第 3 次 | 4s + 抖动 |
| 第 4 次+ | 8s（上限）+ 抖动 |

相比固定间隔，指数退避 + 随机抖动更不易被反爬识别为机器人。
