## 一、整体架构

```
NovelDownloader (class)
├── config            运行时配置（并发/延迟/限频/任务列表/结果映射/取消标志）
├── cache             url → 正文文本 的内存缓存（去重）
├── sites             站点规则表（a / b）
├── currentSite       当前匹配到的站点对象
├── shadowRoot        Shadow DOM 根，隔离 UI 样式
└── 方法集            init / scan / download / parse / extract / save / UI
```

脚本以 `new NovelDownloader()` 启动，构造函数初始化配置后调用 `init()`。

## 三、站点规则表

| 字段 | a（番茄） | b（起点） | 含义 |
|---|---|---|---|
| `host` | `/fanqienovel\.com$/` | `/qidian\.com$/` | hostname 正则匹配 |
| `chapterSelector` | `a.detail-page__catalog-item` | `#chapters .novel-list a` | 目录页章节链接选择器 |
| `numSelector` | `.detail-page__chapter-badge` | （无） | 章节序号节点 |

| `contentSelectors` | 正文容器候选 | 正文容器候选 | 按顺序尝试 |

**标题拼接规则**（[scanChaptersBySite, line 365](file:///d:/devProjects/Crx/viaScript/小说下载器/小说下载器-元素版.user.js#L365)）：
- 有 `numSelector`：`num + ' ' + title` → 「第1章 狂信徒」
- 无 `numSelector`：直接取 `titleSelector` 全文 → 「第1章 平凡的高三日常与内心悸动」

**URL 解析**：直接用 `el.href`，浏览器自动将相对路径（`/novel_chapter/...`、`/novel/...`）转为绝对 URL。

## 六、下载核心

### startDownload（[line 213](file:///d:/devProjects/Crx/viaScript/小说下载器/小说下载器-元素版.user.js#L213)）
1. 按 `selectedIndices` 过滤 `chapterList` 得到 `tasks`
2. 重置 `isDownloading / cancel / completed / resultMap / currentTaskCount`
3. 创建 `concurrency` 个 worker，共享 `index` 指针调用 `scheduleNext`
4. `scheduleNext` 循环：取任务 → `downloadChapter` → 按 `delay`/`adaptiveDelay`/`maxDlPerMin` 休眠
5. 全部完成后调用 `saveFile`

**并发模式**：
- `concurrency > 0`：多线程并发，每线程间隔 `delay` ms
- `concurrency < 0`：单线程，间隔 `|concurrency|` 秒
- `concurrency = 0`：单线程无间隔

### downloadChapter（[line 169](file:///d:/devProjects/Crx/viaScript/小说下载器/小说下载器-元素版.user.js#L169)）
1. 检查 `cancel` 标志
2. 更新进度 UI（`completed+1 / total`）
3. **缓存命中**：直接写入 `resultMap`，`completed++`，return
4. **缓存未命中**：
   - `getHtml(url)` 拉取章节页 HTML
   - `parse(html)` 转 DOMDocument（清洗 a 站点的 `data-novel-info` 属性）
   - `getContent(doc)` 按站点 `contentSelectors` + `contentExtractor` 提取正文
   - `clean()` 规整换行
   - 拼接 `${title}\n\n${content}\n\n` 存入 `resultMap[globalIndex]` 和 `cache`
5. 失败时递归重试，最多 `retryCount` 次，每次间隔 1~2 秒
6. `completed++`，`saveProgress()`

### getContent（[line 110](file:///d:/devProjects/Crx/viaScript/小说下载器/小说下载器-元素版.user.js#L110)）
遍历 `contentSelectors`：
- `querySelector(sel)` 命中 → `extractContent(el, extractor)`
- 结果 `length >= 50` 视为有效，返回
- 全部未命中或过短 → 返回空串

### extractContent（[line 133](file:///d:/devProjects/Crx/viaScript/小说下载器/小说下载器-元素版.user.js#L133)）
1. `cloneNode(true)` 克隆容器
2. 移除 `script/style/noscript/iframe/svg/img/...` 及广告/评论/导航等类名节点
3. 按提取器类型分流：
   - `divLine`：取所有 `div.line`，文本 join `\n\n`
   - `pTags`：取所有 `p`，文本 join `\n\n`
   - 兜底：`clone.textContent`

## 七、文件保存

### saveFile（[line 285](file:///d:/devProjects/Crx/viaScript/小说下载器/小说下载器-元素版.user.js#L285)）
1. **确定文件名**：
   - 优先用 `currentSite.titleSelectors` 在当前页面查小说总标题
   - 回退到 `<title>` 标签
   - 替换非法字符 `[<>:"/\\|?*]` 为 `_`
2. **拼接正文**：
   - 首行写小说名
   - 按 `globalIndex` 升序遍历 `resultMap`，依次拼接
3. **触发下载**：
   - `Blob` + `URL.createObjectURL` + 隐藏 `<a download>` 点击
   - 兼容老 IE 的 `msSaveOrOpenBlob`

## 九、进度持久化

| 方法 | 作用 | 存储键 |
|---|---|---|

## 十、配置项说明（用户可调）

| 配置 | 默认 | 含义 |
|---|---|---|
| `maxConcurrency` | 20 | 并发线程数；负数表示单线程+延时 |
| `delay` | 0 | 每章间隔毫秒 |
| `adaptiveDelay` | true | 自适应延迟（注：当前实现存在死代码，详见已知问题） |
| `maxDlPerMin` | 0 | 每分钟下载上限，0=不限 |
| `retryCount` | 5 | 单章失败重试次数 |

## 十一、已知逻辑问题（详见此前评审）

1. **并发 `index` 竞态**：worker 共享 `index` 但 `await` 后才自增，导致重复下载+跳章
2. **`getHtml` 不校验 HTTP 状态**：403/404 错误页会被当正文
3. **`saveProgress` 存全量正文**：localStorage 易爆配额
4. **取消无法中断在途请求**：`cancel` 标志仅在 `downloadChapter` 入口检查
5. **`maxDlPerMin` 限频失效**：多 worker 共享计数器无同步
6. **`adaptiveDelay` 死代码**：被 `delay > 0` 分支永远短路
7. **断点续传被 `scanChapters` 覆盖**：恢复的 `chapterList/resultMap` 在重新扫描时清空
8. **a 站点 `divLine` 失败走 `textContent` 兜底**：会混入导航/评论文本

## 十三、扩展新站点

1. 在 `sites` 添加配置：
   ```js
   c: {
     name: 'c',
     host: /example\.com$/,
     chapterSelector: '...',
     titleSelector: '...',
     titleSelectors: ['...'],
     contentSelectors: ['...'],
     contentExtractor: 'divLine' | 'pTags',
   }
   ```
2. 如有特殊 HTML 清洗需求，可在 `parse()` 中按 `location.hostname` 分支处理
3. `matchSite()`、`scanChapters()` 已支持任意数量站点，无需改动
