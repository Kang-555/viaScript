# 图片下载器-元素匹配

## 简介

漫画专用批量下载工具，通过**提取链接并拼接URL**的方式快速获取图片。无需等待懒加载，直接根据模板生成完整的图片地址列表进行下载。

## 核心特点

- **URL拼接获取**：提取模板链接，按规律拼接生成所有图片地址
- **无需懒加载**：不需要滚动页面，直接构造URL下载
- **智能解析**：自动提取作品号、识别页码位数和文件格式
- **失败重试**：自动重试失败图片，生成失败清单

## 适用场景

- 漫画网站有固定的图片命名规则（如 `001.jpg`、`002.jpg`...）
- 图片地址按页码规律排列
- 需要从页面提取作品ID和模板URL
- 页面使用分页懒加载，无法一次性扫描到所有图片

## 使用方法

### 步骤1：解析作品号

点击「解析作品号」按钮，脚本会自动从以下位置提取6位数字ID：

1. **优先**：当前地址栏URL（包含 `.html` 和 `-`）
2. **其次**：页面中 class 包含 `btn` 的链接（文本包含"下载漫画"或链接包含 `-`）
3. **最后**：所有包含"下载漫画"文本的链接

提取成功后会显示作品号（格式：`xxxx/xx`），并显示「解析模板链接」按钮。

**失败处理**：如果解析失败，请检查页面是否有包含作品号的链接。

### 步骤2：解析模板链接

点击「解析模板链接」按钮，脚本会：

1. 在 `div#content` 区域内查找包含作品号的图片
2. 提取第一张图片的完整URL作为模板
3. 自动识别：
   - **页码位数**：如 `001` 是3位，`0001` 是4位
   - **文件格式**：jpg、png、webp 等

解析成功后会显示模板URL，并出现输入框。

**失败处理**：如果解析失败，请确保页面中有 `div#content` 容器，且其中包含对应作品号的图片。

### 步骤3：输入总页数

在输入框中填写漫画的**总页数**（数字）：

- 脚本根据模板自动生成所有图片URL
- 例如输入 `100`，会生成 `001.jpg` ~ `100.jpg` 的完整列表
- 输入完成后自动显示「打包下载」按钮

### 步骤4：打包下载

点击「打包下载」按钮：

1. **并发下载**：最多6个同时下载，显示进度 `1/100`
2. **失败重试**：首次下载失败的图片会自动重试3次
3. **查漏补缺**：首次下载完成后，对失败图片进行第二轮补漏下载
4. **生成清单**：仍有失败的图片会生成 `_下载失败清单.txt` 记录到ZIP中
5. **保存文件**：自动生成ZIP文件，使用网页标题作为文件名

## 技术细节

- **作品号格式**：6位数字 → 分割为 `前4位/后2位`
- **图片路径**：`{host}/data/{book}/{chap}/{页码}.{扩展名}`
- **并发限制**：最多6个同时下载
- **超时时间**：15秒（比简单版更长，适合大图）
- **重试次数**：3次
- **补漏机制**：首轮失败后自动进行第二轮补漏下载

## 注意事项

| 问题 | 解决方案 |
|------|----------|
| 解析作品号失败 | 检查页面是否有包含6位数字ID的链接 |
| 解析模板链接失败 | 确保页面有 `div#content` 且包含对应作品号的图片 |
| 下载大量图片失败 | 可能是网站有防盗链或频率限制，建议减少并发或分批下载 |
| 页数输入错误 | 输入框只能输入数字，输入完成后才会显示打包按钮 |

## 与「简单版」的区别

| 对比项 | 元素匹配版 | 简单版 |
|--------|-----------|--------|
| 工作原理 | 提取模板URL，拼接生成地址 | 扫描已加载的图片元素 |
| 懒加载要求 | ✅ 无需等待懒加载 | ⚠️ 必须手动滚动加载所有图片 |
| 适用网站 | 漫画站点（需固定URL规则） | 通用，任何网站 |
| 操作步骤 | 4步（解析作品号→解析模板→输入页数→打包） | 2步（扫描→打包） |
| 智能程度 | 智能提取，自动拼接 | 简单直接 |
| 失败处理 | 自动重试3次 + 补漏 + 失败清单 | 无重试，直接跳过 |
| 推荐场景 | 多页漫画、分页加载的站点 | 单页图片合集、已加载完成的页面 |

## 适用网站特征

本脚本适用于具有以下特征的漫画网站：

1. **作品号系统**：使用6位数字ID标识作品
2. **固定URL规律**：图片地址遵循固定格式，如 `/data/1234/56/001.jpg`
3. **顺序页码**：图片按页码顺序命名，位数固定
4. **div#content**：页面内容包裹在 `id="content"` 的容器中
