# 漫画数据提取 —— 接口位置与方法说明

## 一、数据藏匿位置

所谓"接口"并非独立的 API，而是**漫画章节页面自身的 HTML 源码文件**。

| 项目 | 说明 |
|---|---|
| 页面 URL | 浏览器地址栏里那个 `photos-item-aid-xxxxx.html` |
| Network 面板里 | Name 列的 `.html` 主文档条目 |
| Response 内容 | 服务器返回的原始 HTML 文本 |

HTML 源码里嵌着一段 `<script>` 标签，里面调用了 `mReader.initData(...)`，**数据就藏在这个函数的参数里**。

## 二、数据结构

```javascript
mReader.initData({
    "page_url": [
        "http://img4.qy0.ru/data/2352/75/01_01.jpg?verify=1792886400-xxx",
        "http://img4.qy0.ru/data/2352/75/01_02.jpg?verify=1792886400-yyy",
        "http://img4.qy0.ru/data/2352/75/01_03.jpg?verify=1792886400-zzz"
    ],
    "page_size": [[720, 9074], [720, 7092]],
    "chapter_type": 0,
    "chapter_num": 1
});
```

| 字段 | 类型 | 说明 |
|---|---|---|
| **`page_url`** ⭐ | `string[]` | **目标字段**，完整图片链接数组，每条都带 `?verify=...` 签名，可直接请求 |
| `page_size` | `number[][]` | 每张图的像素尺寸 `[宽, 高]`，非必需 |
| `chapter_type` | `number` | 章节类型，非必需 |
| `chapter_num` | `number` | 章节号，非必需 |

## 三、两种提取场景

### 场景 A：浏览器内油猴脚本

页面 JS 已执行，数据变成了浏览器内存里的对象，**直接取就行**。

#### 方式 1：访问全局对象（最优先）

```javascript
// 普通 window
if (window.mReader?.initData?.page_url) {
    const urls = window.mReader.initData.page_url;
}

// 油猴安全沙箱里必须用 unsafeWindow
if (unsafeWindow.mReader?.initData?.page_url) {
    const urls = unsafeWindow.mReader.initData.page_url;
}
```

#### 方式 2：遍历全局找 page_url 兜底

```javascript
for (const key of Object.keys(unsafeWindow)) {
    try {
        const v = unsafeWindow[key];
        if (v && typeof v === "object" && Array.isArray(v.page_url) && v.page_url.length > 2) {
            console.log("命中: global." + key + ".page_url", v.page_url);
            break;
        }
    } catch (_) {}
}
```

#### 方式 3：正则扫 HTML 源码

```javascript
const html = document.documentElement.outerHTML;
const m = html.match(/"page_url"\s*:\s*(\[[\s\S]*?\])/);
if (m) {
    const urls = JSON.parse(m[1]);
}
```

#### 方式 4：GM_xmlhttpRequest 重新请求源码

```javascript
// @grant GM_xmlhttpRequest
GM_xmlhttpRequest({
    method: "GET",
    url: location.href,
    responseType: "text",
    onload: res => {
        const m = res.responseText.match(/"page_url"\s*:\s*(\[[\s\S]*?\])/);
        if (m) {
            const urls = JSON.parse(m[1]);
        }
    }
});
```

### 场景 B：Python 爬虫

不进浏览器，直接请求页面源码，用正则截出来再 JSON 解析。

```python
import re
import json
import requests

headers = {
    "User-Agent": "Mozilla/5.0 (Linux; Android 14; Pixel 8) AppleWebKit/537.36 Chrome/129.0.0.0 Mobile Safari/537.36"
}

# 1. 请求页面
url = "http://photos-item-aid-235275.html"  # 替换为实际章节 URL
resp = requests.get(url, headers=headers, timeout=15)
html_text = resp.text

# 2. 正则截取 page_url 数组
pattern = r'"page_url"\s*:\s*(\[.*?\])'
match = re.search(pattern, html_text, re.DOTALL)

if match:
    raw_json = match.group(1)     # '[ "链接1", "链接2", ... ]'
    urls = json.loads(raw_json)    # Python list
    print(f"共提取 {len(urls)} 条链接")
    for u in urls:
        print(u)
else:
    print("未找到 page_url")
```

## 四、油猴脚本扫描策略（多层保险）

新脚本 **`漫画page_url提取器.user.js`** 采用四层回退策略：

```
扫描按钮点击
    │
    ├─ ① extractFromGlobal()
    │     直接读 unsafeWindow.mReader.initData.page_url
    │     + 遍历全局找任何含 page_url 的对象
    │     ✅ 命中率最高（95%+）
    │
    ├─ ② extractFromHtmlSource()
    │     正则扫 document.documentElement.outerHTML
    │     ✅ 兼容 DOM 已更新但全局对象丢失的情况
    │
    ├─ ③ fetchHtmlSource() + GM_xmlhttpRequest
    │     绕过浏览器重新请求原始 HTML
    │     ✅ 解决 outerHTML 被浏览器序列化转换的问题
    │
    └─ ④ extractFromAttrs()
          退回 DOM 属性扫描（img.src / data-src 等）
          ✅ 兜底用，前三层全挂才用
```

每一层命中后面板底部会显示 **`来源: xxx`**，方便定位是哪层生效。

## 五、URL 清洗

部分网站返回的 URL 带有模板字符串反引号或引号包裹：

```
`http://img4.qy0.ru/...`      ← 带反引号的模板字符串
'http://cdn.xxx.com/...'      ← 带单引号
```

脚本内部自动清洗：

```javascript
let fixed = u.replace(/^`|`$/g, "").replace(/^['"]|['"]$/g, "").trim();
try { fixed = new URL(fixed, location.href).href; } catch (_) {}
```

## 六、图片 URL 直接可用

`page_url` 里的每条链接**自带 `?verify=...` 签名**，可以直接请求下载，无需额外处理：

```
curl -L "http://img4.qy0.ru/data/2352/75/01_01.jpg?verify=1792886400-bK4yTS..." \
  -H "Referer: http://原始章节页地址.html" \
  -o "01_01.jpg"
```

唯一需要的请求头：`Referer` 设为原始章节页 URL（部分 CDN 防盗链）。
