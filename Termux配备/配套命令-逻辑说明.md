# 配套命令.sh — 逻辑说明

## 用途
在 Termux 上自动执行 `/sdcard/Download` 目录下的 `.txt` 脚本文件（每个 txt 里可写多个视频下载链接），**实时显示下载进度**，并记录成功/失败日志。成功执行后自动从最后下载的视频文件名解析集数。

## 执行方式
脚本本身是一个 **heredoc 包装器**，运行后会在当前目录生成可执行文件 `c`：
```bash
bash 配套命令.sh
./c
```

## 目录结构
| 路径 | 用途 |
|------|------|
| `/sdcard/Download/` | 待处理的 `.txt` 脚本放这里，下载的 mp4 也在这 |
| `/sdcard/Download/exec_success/success.log` | 成功日志（追加写入） |
| `/sdcard/Download/exec_fail/fail_原文件名.log` | 失败日志（每个文件单独一个） |

## 主流程

```
┌─ while true ───────────────────────────────────────────────┐
│                                                              │
│  1. find 捞一个 .txt（捞到什么处理什么，无列表快照）         │
│     └─ 没捞到 → 打印"无待处理txt" → break 退出               │
│                                                              │
│  2. 用 grep 检查 txt 是否有有效命令                           │
│     有效命令 = 非空行 且 非 # 注释行                           │
│     └─ 全是空/注释 → 删除 txt → continue 回到 1             │
│                                                              │
│  3. bash 执行 txt，stdout + stderr 经 tee 同时：             │
│     ├─ 实时打印到终端（能看到 yt-dlp 进度、每个下载提示）    │
│     └─ 写入临时文件 TMP_OUTPUT 供后续解析                    │
│     EXIT_CODE=${PIPESTATUS[0]}（取管道中 bash 的退出码）     │
│                                                              │
│  4. 成功/失败分支                                            │
│     ├─ 成功（退出码=0）                                      │
│     │    a. 从临时输出 grep 最后一个 xxx_数字.mp4            │
│     │       没找到 → 去 Download 目录按 mtime 兜底          │
│     │    b. 用正则 _([0-9]+)\.mp4 解析集数 → "第X集"         │
│     │    c. 追加写入 success.log                            │
│     │    d. 终端打印 📥 下载完成！集数: 第X集                │
│     └─ 失败（退出码≠0）                                     │
│          cat 临时输出 → 写入 fail_原文件名.log               │
│                                                              │
│  5. 清理：rm -f TMP_OUTPUT + rm -f 已执行的 txt             │
│                                                              │
│  6. 交互等待（read -t 10）                                   │
│     ├─ 输入 Y（不区分大小写） → 继续                        │
│     ├─ 10 秒无输入           → 自动继续                    │
│     └─ 输入其他任何字符      → exit 0 结束脚本              │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 集数解析规则
从**最后一个成功下载的视频文件名**中提取，格式要求：`前缀_数字.mp4`

| 最后下载的文件名 | 解析结果 |
|---|---|
| `庆余年_03.mp4` | `第03集` |
| `大明王朝1566_12.mp4` | `第12集` |
| `random.mp4`（无 `_数字.mp4`） | `未识别` |

解析优先级：临时输出里 grep 匹配 → Download 目录按 mtime 兜底 → 正则提取。

## 成功日志格式（success.log，追加）
```
[2026-10-25 15:02:30]
序号: 1
集数: 第03集
下载文件: 庆余年_03.mp4
执行脚本: download_qingyunian.txt
完成情况: 成功 (退出码=0)
------------------------
```

## 失败日志格式（fail_原文件名.log，每个文件独立）
```
[2026-10-25 15:03:05]
执行脚本: bad.txt
退出码: 127
报错消息:
bash: line 1: commandnotfound: command not found
```

## 关键设计点
- **实时输出**：不用 `OUTPUT=$(bash ...)` 攒输出，改用 `bash ... | tee 临时文件`，终端能实时看到下载进度、每个视频的下载提示
- **PIPESTATUS 取退出码**：因为用了管道 `| tee`，`$?` 拿到的是 tee 的退出码，必须用 `${PIPESTATUS[0]}` 取管道第一个命令（bash）的退出码才准确
- **临时文件自动清理**：每个 txt 处理完（无论成功/失败）都 `rm -f $TMP_OUTPUT`，不留残留垃圾
- **无列表快照**：每次 while 循环都 `find ... -print -quit` 取当前目录的第一个 txt，目录内容实时变更也能处理
- **全量删除**：无论空文件、成功、失败，处理完的 txt 一律删除，不留残留
- **退出码判定**：只认 `$? -eq 0` 为成功，任何非 0 都归入失败
- **单日志 vs 多日志**：成功汇总到一个文件方便统计，失败每个独立文件方便定位具体报错
