# 配套命令.sh — 逻辑说明

## 用途
在 Termux 上自动执行 `/sdcard/Download` 目录下的 `.txt` 脚本文件，并记录成功/失败日志。

## 执行方式
脚本本身是一个 **heredoc 包装器**，运行后会在当前目录生成可执行文件 `c`：
```bash
bash 配套命令.sh
./c
```

## 目录结构
| 路径 | 用途 |
|------|------|
| `/sdcard/Download/` | 待处理的 `.txt` 脚本放这里 |
| `/sdcard/Download/exec_success/success.log` | 成功日志（追加写入） |
| `/sdcard/Download/exec_fail/fail_原文件名.log` | 失败日志（每个文件单独一个） |

## 主流程

```
┌─ while true ─────────────────────────────────────────┐
│                                                       │
│  1. find 捞一个 .txt（捞到什么处理什么，无列表快照）  │
│     └─ 没捞到 → 打印"无待处理txt" → break 退出        │
│                                                       │
│  2. 用 grep 检查 txt 是否有有效命令                    │
│     有效命令 = 非空行 且 非 # 注释行                    │
│     └─ 全是空/注释 → 删除 txt → continue 回到 1        │
│                                                       │
│  3. bash 执行 txt，stdout + stderr 全部捕获到 OUTPUT   │
│     ├─ 退出码 = 0  → 追加写入 success.log              │
│     └─ 退出码 ≠ 0  → 写入 fail_原文件名.log（覆盖）   │
│                                                       │
│  4. 删除已执行的 txt                                   │
│                                                       │
│  5. 交互等待（read -t 10）                            │
│     ├─ 输入 Y（不区分大小写） → 继续                   │
│     ├─ 10 秒无输入           → 自动继续               │
│     └─ 输入其他任何字符      → exit 0 结束脚本         │
│                                                       │
└───────────────────────────────────────────────────────┘
```

## 成功日志格式（success.log，追加）
```
[2026-10-25 14:30:00]
序号: 1
文件名: test.txt
完成情况: 成功 (退出码=0)
------------------------
```

## 失败日志格式（fail_原文件名.log，每个文件独立）
```
[2026-10-25 14:30:05]
文件名: bad.txt
退出码: 127
报错消息:
bash: line 1: commandnotfound: command not found
```

## 关键设计点
- **无列表快照**：每次 while 循环都 `find ... -print -quit` 取当前目录的第一个 txt，目录内容实时变更也能处理
- **全量删除**：无论空文件、成功、失败，处理完的 txt 一律删除，不留残留
- **退出码判定**：只认 `$? -eq 0` 为成功，任何非 0 都归入失败
- **单日志 vs 多日志**：成功汇总到一个文件方便统计，失败每个独立文件方便定位具体报错
