# m3u8 可视化拖拽选段下载 — 优化思路

---

## 一、架构层面

### 1.1 模块化拆分
**现状**：所有逻辑集中在一个 IIFE 中，Sniffer / TSPacketFixer / VideoWriter / MultiSegmentWriter / SimpleUI 互相耦合。

**优化方向**：
- 按职责拆分为独立模块（嗅探器、下载器、解析器、UI 管理器、时间戳修复器）
- 每个模块暴露清晰的接口，通过事件总线或依赖注入通信
- 便于单独测试和替换实现（如将来用 Web Worker 处理时间戳修复）

### 1.2 状态管理
**现状**：`SimpleUI.resources`、`item._cutSegments`、`item._parsedM3u8` 分散在各处，缺乏统一状态。

**优化方向**：
- 引入集中式状态 Store（简单的发布-订阅模式即可）
- 资源解析状态、下载进度、时间段数据全部收口到 Store
- UI 只关心渲染，不直接操作业务数据

### 1.3 配置系统
**现状**：并发数（CONCURRENCY=6）、超时（60000ms）、下载间隔（500ms）等硬编码在函数内部。

**优化方向**：
- 提取为可配置项，支持 GM_setValue 持久化
- 暴露设置面板让用户调整：并发数、超时时间、分片下载间隔、默认滑块范围等

## 二、嗅探器优化

### 2.1 当前问题
- `scanPerformance()` 每 2 秒轮询一次 `performance.getEntriesByType('resource')`，性能开销不必要
- 只匹配 m3u8 后缀，不支持 MP4/MOV（文档中提到但代码中已移除）
- `seenUrls` 只按 URL 去重，同一资源不同查询参数可能重复

### 2.2 优化方向

| 优化项 | 说明 |
|--------|------|
| **MutationObserver 替代轮询** | 监听 `<video>` / `<source>` 元素的 `src` 属性变化，直接捕获 m3u8 URL |
| **MP4/MOV 嗅探恢复** | 扩展 rules 正则，支持 `.mp4`、`.mov`、`.webm` 等直链视频 |
| **智能去重** | 对 URL 做规范化处理（去除 tracking 参数）后再去重 |
| **MediaSource 嗅探** | Hook `MediaSource.prototype.addSourceBuffer`，捕获动态生成的 m3u8 |
| **iframe 穿透** | 检测 iframe 中的 video 元素（需用户确认是否需要跨域） |

## 三、下载性能优化

### 3.1 并发策略
**现状**：固定 6 并发，每批 await Promise.all(batch)，批次间串行。

**问题**：
- 网络好时 6 并发是瓶颈，网络差时 6 并发可能导致超时
- 批次间串行导致整体延迟大

**优化方向**：
- **动态并发**：根据实时下载速度自适应调整（速度 > 2MB/s 时提高到 12，< 500KB/s 时降到 3）
- **流水线下载**：前一批完成 2 个就开始补充，而非等整批完成
- **分片合并下载**：相邻分片合并为一个请求，减少 HTTP 开销（适合同一 CDN）

### 3.2 断点续传
**现状**：下载失败直接填零占位，不重试。

**优化方向**：
- 单个分片失败自动重试（指数退避，最多 3 次）
- 记录已下载分片索引，刷新页面后可断点续传
- 使用 localStorage 持久化下载进度

### 3.3 内存优化
**现状**：所有分片 buffer 同时保存在 `VideoWriter.buffers` 中，大视频可能数百 MB。

**优化方向**：
- 边下边写：每个分片下载完成后立即进行时间戳修复并写入 Blob，不累积
- 使用 `Blob` 的 `append` 方法流式拼接，而非累积到数组后一次性 new Blob
- 超大视频（>500MB）给出内存警告，建议分段下载

### 3.4 下载速度显示
**现状**：`gmRequest` 中有 speed 计算但未暴露给用户。

**优化方向**：
- 面板实时显示当前下载速度（KB/s 或 MB/s）
- 显示 ETA（预计剩余时间）
- 显示已下载总量 / 预估总量

## 四、时间戳修复优化

### 4.1 当前问题
- `getPCRRanges` 对每个分片遍历所有 TS 包（188 字节对齐），大文件 CPU 开销不小
- `applyTimestampOffset` 创建了新的 Uint8Array 副本，内存翻倍

### 4.2 优化方向

| 优化项 | 说明 |
|--------|------|
| **原地修改** | 直接在原始 buffer 上修改 PCR/PTS/DTS，避免 Uint8Array 拷贝 |
| **增量修复** | 每下载完一个分片立即修复并拼接，不累积后一次性处理 |
| **Web Worker** | 将时间戳修复放到 Worker 线程，不阻塞主线程 UI |
| **缓存策略** | 同一 m3u8 多次下载时复用已计算的偏移量 |

### 4.3 边界情况
- `#EXT-X-DISCONTINUITY` 标记的分片时间戳不连续，当前未特殊处理
- 实况流（LL-HLS）的时间戳可能循环，需处理回绕

## 五、UI/UX 优化

### 5.1 可视化选段
**现状**：两个独立滑块，体验不够直观。

**优化方向**：
- **双滑块合并**：在同一轨道上显示两个可拖动的滑块，中间高亮选中区域
- **波形预览**：显示视频音频波形，帮助用户精准定位（可选）
- **快捷键支持**：←/→ 逐帧微调，空格播放/暂停
- **秒级精准**：滑块旁增加数字输入框，直接输入秒数
- **标记常用时段**：标记开头（片头）、中间、结尾，一键选择

### 5.2 面板交互
- **拖拽排序**：资源列表支持拖拽排序
- **资源重命名**：双击资源名可自定义名称
- **历史记录**：记录已下载的时间段，方便重复下载
- **快捷键呼出**：`Ctrl+Shift+D` 快速唤起面板
- **最小化模式**：面板缩小为极简状态条，显示当前下载进度

### 5.3 移动端适配
**现状**：移动端可使用但体验一般。

**优化方向**：
- 触摸优化的滑块（更大触摸区域，50px+）
- 横屏模式下自动调整布局
- 支持音量键微调时间段

## 六、安全与稳定性

### 6.1 错误处理
**现状**：错误直接 alert，用户体验差，且未分类。

**优化方向**：
- 统一错误码和友好提示（如 "网络错误" / "视频源加密无法解密" / "浏览器不支持"）
- 自动恢复：解析失败时自动重试一次
- 日志系统：`console.debug` 记录详细错误，用户可导出诊断

### 6.2 兼容性
- 部分浏览器不支持 `crypto.subtle`（需 HTTPS 或 localhost），应降级到异步加载 CryptoJS
- `GM_xmlhttpRequest` 在某些沙盒环境受限，应检测并提示
- hls.js 加载失败时，回退到原生 `<video>` 播放

### 6.3 内存泄漏
- `hlsInst` 只在 `closeOverlay` 中 destroy，异常关闭可能泄漏
- `Bus.events` 未清理，反复 init 会导致回调重复注册
- `MutationObserver` 在 init 完成后未 disconnect

## 七、功能增强

### 7.1 下载输出
- **FLV 封装**：除 TS 外支持 FLV 封装（部分播放器兼容性更好）
- **MP4  remux**：使用 mp4box.js 将 TS 转封装为 MP4（需引入 mp4-muxer 库）
- **GIF 截取**：支持将选定时间段导出为 GIF
- **音频提取**：单独导出音频轨道（AAC/MP3）

### 7.2 批量操作
- 同一 m3u8 的多个时间段一键打包为 ZIP
- 不同 m3u8 资源的时间段合并下载
- 预设时间段模板（如"每 5 分钟一段"自动切分）

### 7.3 智能辅助
- **片头片尾检测**：自动识别片头片尾标记，建议跳过
- **关键帧对齐**：选段起止自动对齐到最近的关键帧，避免花屏
- **分辨率检测**：显示当前 m3u8 分辨率，多码率时可切换

## 八、代码质量

### 8.1 可维护性
- 将大函数（`openPreviewSelectSegment` 近 160 行）拆分为子函数
- `createElement` 可考虑使用 tagged template 或轻量 JSX 替代
- 统一错误处理模式（try-catch → Promise.catch → async/await）

### 8.2 性能监控
- 埋点记录：解析耗时、下载总耗时、时间戳修复耗时
- 自监控：发现内存使用异常时自动警告

## 九、优先级建议

| 优先级 | 优化项 | 预期收益 |
|--------|--------|---------|
| **P0** | 分片下载失败重试 + 断点续传 | 解决最痛的下载失败问题 |
| **P0** | 内存优化（边下边写） | 支持更大视频下载 |
| **P1** | 双滑块合并 + 波形预览 | 选段体验质的飞跃 |
| **P1** | 动态并发策略 | 下载速度提升 30-50% |
| **P1** | 错误分类 + 友好提示 | 降低用户困惑 |
| **P2** | Web Worker 时间戳修复 | 大视频不卡顿 |
| **P2** | MP4 remux 输出 | 更好的播放兼容性 |
| **P2** | 嗅探器优化（MutationObserver） | 降低 CPU 占用 |
| **P3** | 批量操作 / 预设模板 | 提升批量下载效率 |
| **P3** | 代码模块化重构 | 长期可维护性 |
