# m3u8 多段下载逻辑总结

## 整体流程

```
用户点击"开始下载"
    ↓
UI._startDownload()
    ├─ 单段: opt = { ranges: [{start, end}] }
    └─ 多段: opt = { ranges: [{start1,end1}, {start2,end2}, ...] }
    ↓
TaskRunner(url, 'm3u8', btn, opt)
    ├─ 1. parseM3u8(url) → 解析m3u8，提取分片URL/密钥/时长
    ├─ 2. 时间→分片索引换算
    │   ├─ 单段: [0,1,2,3]
    │   └─ 多段: [0,1,2,3,12,13,14,15] (去重排序)
    ├─ 3. 获取AES密钥（如有加密）
    └─ 4. downloadM3u8BySegments() → 并发下载指定分片
    ↓
VideoWriter.buffers[] → 所有分片buffer
    ↓
TSPacketFixer.fixTimestamps() → 修复时间戳连续性
    ↓
writer.close(filename) → 拼接Blob，触发下载
```

---

## 关键模块

### 1. parseM3u8(url)
- 解析 m3u8 文件，提取分片信息
- 支持多码率自动选最高
- 解析 `#EXT-X-KEY` 加密信息
- 解析 `#EXT-X-DISCONTINUITY` 断点标记
- 返回：`{ segments, keyUrls, timeList }`

### 2. timeToSegmentIndex(timeList, beginSec, endSec)
- 时间段 → 分片索引映射
- 累加 `#EXTINF` 时长定位分片
- 返回：`{ startIdx, endIdx }`

### 3. downloadM3u8BySegments(segments, keyCache, onProgress, writer, segmentIndices)
- **4线程并发**下载分片
- 失败重试 **3次**（指数退避：1s→2s→4s→8s）
- 支持 AES-128 自动解密
- 无 IV 时自动用分片序号生成 IV
- 实时进度：百分比/速度/ETA

### 4. AES-128 解密
- 自动下载密钥到 `keyCache` Map
- `crypto.subtle.decrypt()` 解密分片
- 无 IV 时：`new Uint8Array(16)` 前12字节为0，后4字节为分片序号（大端序）

### 5. TSPacketFixer.fixTimestamps(buffers)
- 修复分片拼接后的时间戳不连续问题
- 修复范围：**PCR**（节目时钟参考）、**PTS**（显示时间戳）、**DTS**（解码时间戳）
- 时间单位：**90kHz**（1秒 = 90000）
- 原理：计算相邻分片 gap，对后续分片累加偏移量

### 6. VideoWriter
- 内存中拼接所有分片 buffer
- `new Blob(buffers, { type: 'video/mp2t' })`
- 触发浏览器下载 `.ts` 文件

## 多段下载修复

### 问题原因
`_startDownload()` 中多段模式只取了 `minStart` 和 `maxEnd`，导致下载了中间不需要的分片。

### 修复内容

| 位置 | 修改 |
|------|------|
| **downloadM3u8BySegments** | 参数从 `startIdx, endIdx` 改为 `segmentIndices` 数组，只下载指定索引的分片 |
| **TaskRunner** | 将多个时间段分别换算为分片索引，合并去重后传入 |
| **_startDownload** | 直接传递 `ranges` 数组，显示精确的分片数量 |

### 修复后效果

```
用户选择：0-10s 和 30-40s（共2段）

修复前：下载 0-40s 所有分片（包含中间不需要的10-30s）
修复后：只下载 0-10s 和 30-40s 对应的分片
```

### 工作流程

```
_startDownload() → opt = { ranges: [{start:0,end:10}, {start:30,end:40}] }
    ↓
TaskRunner() → 时间段1换算为分片[0,1,2,3] + 时间段2换算为分片[12,13,14,15]
    ↓
segmentIndices = [0,1,2,3,12,13,14,15]（去重排序）
    ↓
downloadM3u8BySegments() → 只下载这8个分片
    ↓
TSPacketFixer.fixTimestamps() → 修复时间戳连续性
    ↓
输出正确的TS文件
```

## TS 时间戳修复

### 问题
分片简单二进制拼接后，时间戳可能不连续，播放器显示时长异常。

### 原理

```
分片1: PCR 0→900000          (0→10秒)
分片2: PCR 1800000→2700000   (20→30秒) ← 跳跃10秒！

修复后：
分片1: PCR 0→900000
分片2: PCR 900000→1800000   ← 时间戳连续！
```

### 修复范围

| 时间戳 | 说明 | 影响 |
|--------|------|------|
| **PCR** | 节目时钟参考 | 播放器总时长显示 |
| **PTS** | 显示时间戳 | 音视频同步 |
| **DTS** | 解码时间戳 | B帧解码顺序 |

### 时间单位
- **90kHz**（1秒 = 90000）
- 33位最大值约 26.5 小时
