# 下载队列 + Tab面板改造思路

> 基于原方案整合 Tab 切换面板设计，彻底消除弹窗嵌套和自动跳转逻辑。

---

## 1. 当前问题

现在 `单连续下载.user.js` 的下载是 **单任务互锁** 的，UI 是 **弹窗嵌套切换** 的。

两个硬伤：

```
① runDownload 入口直接拒绝
   第1213行: if (this.downloadState.status === 'downloading') return;

② 下载按钮被 disable 绑定
   第1095行: disabled: this.downloadState.status === 'downloading'
```

结果：A 资源正在下载时，B 资源的"选择 → 下载"路径完全走不通。用户必须等 A 下完，或者手动清空取消，才能开始 B。

UI 交互问题：嗅探面板点"选择" → 整个面板内容换成下载表单 → 下载完或取消才能回嗅探面板。**嗅探和下载是互斥的两个视图**，无法边嗅探边看队列。

## 2. 目标

### 2.1 队列目标

```
下载队列 (顺序执行，默认并发数 1)

┌─ 队列管理器 (全局单例) ──────────────────────────┐
│  Task #3 ── 完成 ✓                               │
│  Task #4 ── 正在下载 (进度 65%)  ← 当前 active  │
│  Task #5 ── 等待中                               │
│  Task #6 ── 等待中    ← 用户随时可继续"选择"    │
└──────────────────────────────────────────────────┘
```

核心一句话：**下载和嗅探解耦**。UI 的"选择"按钮永远可用，点击下载后任务丢进队列立即返回；队列自己串行跑，进度实时推回 UI。

### 2.2 面板目标

**单个浮窗 + 顶部 Tab 切换**，不再多个弹窗来回跳转。三个 Tab 聚合在同一个 Shadow DOM 容器里：

```
┌─────────────────────────────────────────────────────┐
│ [嗅探资源]  [下载配置]  [下载队列]                [×] │
├─────────────────────────────────────────────────────┤
│                                                     │
│                ↓ 当前Tab页面内容 ↓                   │
│                                                     │
└─────────────────────────────────────────────────────┘
```

消除弹窗嵌套、自动跳转逻辑，全部由用户手动切换标签。

## 3. 架构变化

### 3.1 原来的状态模型

```
UI {
    downloadState: {     ← 单一状态槽，一次只能装一个
        status: 'idle' | 'downloading' | 'done' | 'error',
        progressText,
        error
    }
    _cancelled: bool,    ← 单一取消标志
    _currentId: number,  ← 防过期回调
    currentPanel: 'sniffer' | 'download'   ← 弹窗互斥
}
```

### 3.2 改造后的状态模型

```
QueueManager (全局单例) {
    tasks: Map<taskId, Task>,        ← 多任务并存
    activeId: number | null,         ← 当前正在跑的那个
    isRunning: bool,                 ← 队列调度器是否活跃
    maxConcurrent: 1,                ← 默认串行，可扩展

    addTask(item, opt) → taskId
    cancelTask(taskId)
    cancelAll()
    removeTask(taskId)
    clearCompleted()
    pause() / resume()
}

Task {
    id: number,
    item: { url, type, filename, ... },
    opt: { startIdx, endIdx, beginSec, endSec },
    status: 'waiting' | 'downloading' | 'done' | 'error' | 'cancelled',
    progress: {
        percent: 0,
        text: '',
        completedCount,
        totalCount,
        totalBytes,
        speed
    },
    cancelFlag: false,
    error: string | null,
    startTime: number,
}
```

### 3.3 UI 的变化

```
UI {
    // 删掉 →  downloadState  (单状态槽彻底废弃)
    // 删掉 →  _cancelled    (每 Task 自带 cancelFlag)
    // 删掉 →  _currentId    (每 Task 自管生命周期)
    // 删掉 →  currentPanel: 'sniffer' | 'download'  (Tab 导航替代)
    // 删掉 →  selectedResource  (由 downloadSettingTab 自己持有)

    // 新增
    queue: QueueManager,
    currentTab: 'sniffer' | 'download-setting' | 'queue',
    settingItem: { url, type, filename, duration, segmentCount, encrypted, parseStatus, ... },
    queueProxies: Map<taskId, UIProxy>,

    // 渲染三个 Tab
    renderTabHeader()
    renderSnifferTab()
    renderDownloadSettingTab()
    renderQueueTab()
    switchTab(name)
}
```

## 4. 核心模块：QueueManager

### 4.1 调度器骨架

```
class QueueManager {
    constructor() {
        this.tasks = new Map();
        this.activeId = null;
        this.isRunning = false;
        this.nextId = 1;
        this.maxConcurrent = 1;
    }

    addTask(item, opt) {
        // 去重：同 URL + 同范围 → 拒绝
        for (const t of this.tasks.values()) {
            if (t.status === 'waiting' || t.status === 'downloading') {
                if (t.item.url === item.url && optEqual(t.opt, opt)) {
                    console.warn('[Queue] 重复任务已拒绝');
                    return -1;
                }
            }
        }
        const taskId = this.nextId++;
        const task = {
            id: taskId,
            item: { ...item },
            opt: { ...opt },
            status: 'waiting',
            progress: { percent: 0, text: '', completedCount: 0, totalCount: 0, totalBytes: 0, speed: 0 },
            cancelFlag: false,
            error: null,
            startTime: Date.now()
        };
        this.tasks.set(taskId, task);
        Bus.emit('queue:task-added', task);
        this.schedule();
        return taskId;
    }

    schedule() {
        if (this.isRunning) return;
        if (this.activeId !== null) return;
        const next = this.findNextWaiting();
        if (!next) return;

        this.isRunning = true;
        this.activeId = next.id;
        next.status = 'downloading';
        Bus.emit('queue:task-start', next);

        this.runTask(next).finally(() => {
            this.activeId = null;
            this.isRunning = false;
            this.schedule();   // 递归调度下一个
        });
    }

    findNextWaiting() {
        for (const t of this.tasks.values()) {
            if (t.status === 'waiting') return t;
        }
        return null;
    }

    async runTask(task) {
        try {
            await TaskRunner(
                task.item.url,
                task.item.type,
                (percent, text, data) => {
                    task.progress.percent = percent;
                    task.progress.text = text;
                    Object.assign(task.progress, data || {});
                    Bus.emit('queue:task-progress', task);
                },
                task.opt,
                () => task.cancelFlag
            );
            task.status = 'done';
            Bus.emit('queue:task-done', task);
        } catch (err) {
            if (task.cancelFlag) {
                task.status = 'cancelled';
                Bus.emit('queue:task-cancelled', task);
            } else {
                task.status = 'error';
                task.error = err.message;
                Bus.emit('queue:task-error', task);
            }
        }
    }

    cancelTask(taskId) {
        const task = this.tasks.get(taskId);
        if (!task) return;
        task.cancelFlag = true;
        if (task.status === 'waiting') {
            task.status = 'cancelled';
            Bus.emit('queue:task-cancelled', task);
        }
    }

    removeTask(taskId) {
        this.tasks.delete(taskId);
        Bus.emit('queue:task-removed', taskId);
    }

    cancelAll() {
        for (const t of this.tasks.values()) {
            if (t.status === 'waiting') {
                t.cancelFlag = true;
                t.status = 'cancelled';
                Bus.emit('queue:task-cancelled', t);
            } else if (t.status === 'downloading') {
                t.cancelFlag = true;
            }
        }
    }

    clearCompleted() {
        for (const [id, t] of this.tasks) {
            if (t.status === 'done' || t.status === 'error' || t.status === 'cancelled') {
                this.tasks.delete(id);
                Bus.emit('queue:task-removed', id);
            }
        }
    }

    get counts() {
        let downloading = 0, waiting = 0;
        for (const t of this.tasks.values()) {
            if (t.status === 'downloading') downloading++;
            else if (t.status === 'waiting') waiting++;
        }
        return { downloading, waiting, total: this.tasks.size };
    }
}
```

### 4.2 事件总线

QueueManager 复用现有 `Bus`（已在 `单连续下载.user.js` 第268行定义），统一前缀 `queue:`：

```
Bus 事件:
  'queue:task-added'     → UI 队列Tab 新增一行
  'queue:task-start'     → UI 状态变 downloading
  'queue:task-progress'  → UI 更新进度文字（150ms 节流已在 TaskRunner 内部做了）
  'queue:task-done'      → UI 状态变 done
  'queue:task-error'     → UI 状态变 error
  'queue:task-cancelled' → UI 状态变 cancelled
  'queue:task-removed'   → UI 移除该行
```

UI 里 `Bus.on('queue:xxx', handler)` 订阅即可，QueueManager 完全不持有 DOM 引用。

## 5. Tab 面板设计

### 5.1 整体 DOM 结构

```
<div class="main-panel">                          ← shadow DOM 根节点
  <div class="tab-header">
    <button class="tab-btn active"  data-tab="sniffer">嗅探资源</button>
    <button class="tab-btn"         data-tab="download-setting">下载配置</button>
    <button class="tab-btn"         data-tab="queue">下载队列</button>
    <button class="close-btn">×</button>
  </div>
  <div class="tab-body">
    <div class="tab-panel active"  data-panel="sniffer">         <!-- Tab1 -->
      <!-- 嗅探列表内容 -->
    </div>
    <div class="tab-panel"         data-panel="download-setting"><!-- Tab2 -->
      <!-- 下载配置表单 -->
    </div>
    <div class="tab-panel"         data-panel="queue">           <!-- Tab3 -->
      <!-- 队列任务列表 -->
    </div>
  </div>
</div>
```

样式用 CSS class `.tab-panel.active { display: block }` 控制，其余 `display: none`。**不再用 innerHTML 整体替换面板内容**，三个 Tab 的 DOM 长期共存、只切换可见性 —— 这样各 Tab 的状态（滚动位置、输入框值、进度文字）切走再切回来都保留，体验好很多。

### 5.5 UIProxy 模式

QueueManager 发事件时只带 Task 数据，UI 通过 UIProxy 关联 DOM：

```
UIProxy {
    taskId,
    rowEl,          ← 这个任务的 .queue-row 元素
    barFillEl,      ← 进度条填充层
    progressTextEl, ← 进度文字
    statusEl,       ← 状态徽标

    bind(task) {
        // 初始渲染整个 row
    }

    updateProgress(task) {
        this.barFillEl.style.width = task.progress.percent + '%';
        this.progressTextEl.textContent = task.progress.text;
    }

    updateStatus(task) {
        // 根据 status 切换徽标 class + 进度文字 + 按钮可用性
    }

    destroy() {
        this.rowEl.remove();
    }
}
```

UI 收到 `bus:queue:task-added` → 创建 UIProxy 并 append 到 Tab3 列表；收到 `task-progress` → 找对应 proxy 调 `updateProgress`；收到 `task-removed` → 调 `destroy`。

### 5.6 switchTab 核心逻辑

```
switchTab(name) {
    if (this.currentTab === name) return;
    this.currentTab = name;

    // Tab header 按钮 active 样式
    this.tabHeader.querySelectorAll('.tab-btn').forEach(b => {
        b.classList.toggle('active', b.dataset.tab === name);
    });

    // Tab body 面板可见性
    this.tabBody.querySelectorAll('.tab-panel').forEach(p => {
        p.classList.toggle('active', p.dataset.panel === name);
    });

    // 切到 Tab2 时自动刷新表单（settingItem 可能已更新）
    if (name === 'download-setting') {
        this.refreshDownloadSettingTab();
    }
    // 切到 Tab3 时刷新队列（新增任务可能在用户离开期间加入）
    if (name === 'queue') {
        this.refreshQueueTab();
    }
}
```

**为什么 Tab 切换时才 refresh 而不是实时更新？**
- Tab3 的进度条需要高频更新，但 DOM 隐藏时不重绘，可以先攒着
- Tab2 的表单内容只在 sniffing tab 选择新资源时才变，切回来时同步一次足够
- 高频更新 + CSS `display: none` = 浏览器跳过绘制，性能几乎零开销

## 6. cancelCheck 机制无缝复用

现在 `TaskRunner` 和 `downloadM3u8BySegments` 里已经有 cancelCheck 闭包：

```
cancelCheck = () => this._cancelled || this._currentId !== myId;
```

改造后变成：

```
cancelCheck = () => task.cancelFlag;
```

**零额外工作** —— `downloadM3u8BySegments` 里的 worker 循环、分片请求之间已经在定期检查 cancelCheck，完全复用。只是把取消标志从 UI 实例的 `_cancelled` 移到了 Task 对象上。

## 7. 生命周期 & 边界情况

### 7.1 用户关闭/刷新页面

油猴脚本 per-tab 运行。关闭 tab → 整个脚本销毁 → GM_xmlhttpRequest 自然断掉。

简化处理：刷新 = 清空队列。**不做持久化**（UserScript 层面没必要，MV3 再说）。

### 7.2 Tab3 在后台看不见时的进度更新

高频的 `queue:task-progress` 事件仍然会发到 Bus，但 UIProxy 的 DOM 元素在 CSS `display: none` 下浏览器不绘制，只是数据写进属性 —— **性能开销极小**。用户切回 Tab3 时 `refreshQueueTab()` 会重新扫一遍所有 task 的最新状态，保证不丢进度。

### 7.3 重复 URL 去重

已在 `QueueManager.addTask` 里处理：同 URL + 同时间/分片范围 → 返回 `-1`，UI 在 Tab2 显示"该资源已在队列中"提示，不报错。

### 7.4 错误恢复

单个任务下载失败：
- 默认策略：标 `status: 'error'`，队列继续跑下一个
- 分片层面已有 `maxRetries = 3` 自动重试，任务层面不再叠加

### 7.5 并发数

当前 `maxConcurrent: 1` 串行。如果想让多个任务同时跑（比如 m3u8 + mp4 并行），改成 2 后调度器调整：

```
schedule() {
    const activeCount = [...this.tasks.values()]
        .filter(t => t.status === 'downloading').length;
    while (activeCount < this.maxConcurrent) {
        const next = this.findNextWaiting();
        if (!next) break;
        this.startTask(next);
    }
}
```

## 9. 改造顺序建议

```
Step 1: 搭 QueueManager 骨架 + 跑通 addTask → schedule → runTask 串行流程（UI 还没接，console.log 验证）
Step 2: UI.init 重构 DOM —— tab-header + tab-body + 三个空的 tab-panel 占位；switchTab 跑通；Tab1 sniffing 渲染跑通（先把原 renderSnifferPanel 塞进 [data-panel="sniffer"]）
Step 3: QueueManager 接到 UI.runDownload —— 点下载 → queue.addTask → TaskRunner 实际执行 → console 看进度回传
Step 4: UI 订阅 Bus queue: 事件 —— Tab3 出现任务行、进度条动起来
Step 5: Tab2 下载配置跑通 —— 嗅 Tab 点【选择】→ settingItem 填充 → switchTab('download-setting') → 表单完整可编辑 → 【加入下载队列】入队成功
Step 6: 取消机制 —— waiting 和 downloading 两种状态的取消都能生效
Step 7: 清理旧代码 —— downloadState / _cancelled / _currentId / currentPanel / selectedResource 全部删除
Step 8: 边界收尾 —— 重复 URL 去重、全部取消、清空已完成、切 Tab 时 refresh 防数据丢失
```

Step 2 + Step 3 可以先做，先不追求 Tab3 的完整样式，能看到 console 日志里 TaskRunner 跑完就算通了，再往里加 UI。

## 10. 相比之前方案简化点

| 原方案（多弹窗） | 新方案（单浮窗 Tab 切换） |
|---|---|
| 嗅探面板点"选择" → 整个面板替换成下载面板 | 切 Tab，嗅探面板内容保留在 DOM 里 |
| 下载面板完成后 1.2s 自动跳回嗅探面板 | 入队后停留 Tab2，用户手动点"返回嗅探" |
| 嗅探面板底部常驻队列摘要条 | 队列信息统一放 Tab3 |
