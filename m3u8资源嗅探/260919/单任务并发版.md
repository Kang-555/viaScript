# M3U8嗅探下载器 · 单任务并发版

> Tampermonkey / Violentmonkey 用户脚本，页面级视频嗅探 + 下载。

---

## 一、模块总览

脚本由 9 个模块按顺序组装，依赖关系从下到上：

```
Sniffer（嗅探） ──emit──▶  Bus（事件总线）  ◀──emit──▶  QueueManager（队列调度）
        │                                                        │
        ▼                                                        ▼
   UI（Tab 面板） ◀──── 通过 Bus 双向通信 ──── TaskRunner（下载引擎）
                                                        │
                                             ┌──────────┼──────────┐
                                             ▼          ▼          ▼
                                        parseM3u8   AESCrypto  downloadMp4
                                             │          │
                                             ▼          ▼
                                     downloadM3u8BySegments（多Worker并发）
                                                        │
                                                        ▼
                                                  VideoWriter（按序合并）
```

## 二、各模块逻辑简述

### 1. 全局配置 `Config`
- 根据 UA 检测是否移动端，自适应线程数（移动端默认 10，桌面 30）
- 桌面端线程上限 50，移动端 15
- 基础颜色、重试次数（3）、重试延迟（指数退避）、分片失败率自适应阈值

### 2. 工具函数库 `Utils`
- **格式化**：字节（B/KB/MB/GB）、时间（秒 → `HH:MM:SS` 或 `MM:SS`）
- **时间输入转换**：`HHmmss` 字符串 ↔ 秒数
- **网络请求**：基于 `GM_xmlhttpRequest` 封装 Promise 接口，支持进度回调、取消检测、二进制/文本模式、60s 超时
- **DOM 创建**：统一属性 → attrs/事件/style 处理
- **文件下载**：`Blob` + `URL.createObjectURL` 触发浏览器下载
- **URL 解析**：相对 URL → 绝对 URL

### 3. AES-128 解密模块 `AESCrypto`
- `hexToBytes`：密钥十六进制字符串 → `Uint8Array`
- `sequenceToIV`：无 IV 时，用分片序号填充 16 字节 IV（大端序）
- `decrypt`：调用浏览器原生 `crypto.subtle.decrypt`（AES-CBC）

### 4. 事件总线 `Bus`
- 极简发布/订阅：`on(event, cb)` / `emit(event, data)`
- 解耦嗅探器、队列、UI 三者

### 5. 网络嗅探器 `Sniffer`（核心）
**三种嗅探方式同时启用**：

| 方式 | 原理 | 覆盖场景 |
|------|------|----------|
| Hook `fetch` | 替换 `unsafeWindow.fetch`，克隆 response 读取 Content-Type | 现代 fetch 请求 |
| Hook `XHR` | 继承原生 `XMLHttpRequest`，`readyState===4` 时取 Content-Type | 传统 AJAX |
| `performance` 扫描 | `setInterval` 每 2s 遍历 `getEntriesByType('resource')` | 静态资源加载 |

**过滤规则**：
- 黑名单：`data:` / `blob:` / 图片/css/js/woff/svg
- 去重：URL 去掉 query 后存入 `Set`
- 命中正则 → `Bus.emit('video-found', { url, type })`

### 6. 下载引擎

#### 6.1 M3U8 解析 `parseM3u8`
1. 拉取 m3u8 文本
2. **多码率处理**：存在 `#EXT-X-STREAM-INF` 时，选带宽最大的子清单递归解析
3. 遍历每一行：
   - `#EXT-X-KEY` → 解析 METHOD/URI/IV，保存当前密钥
   - `#EXT-X-MEDIA-SEQUENCE` → 起始分片序号
   - `#EXTINF` → 当前分片时长
   - 普通行 → 生成 `segObj`（url、key、iv、seq、dur），累计时间戳
4. 返回 `{ segments[], timeList[], totalDuration, targetDuration }`

#### 6.2 时间 → 分片索引 `timeToSegmentIndex`
二分遍历 `timeList`，根据用户输入的起止时间找到对应的分片索引范围

#### 6.3 多线程并发下载 `downloadM3u8BySegments`
**Worker 池模式**：
- 初始 Worker 数 = `min(maxThreads, 分片数)`
- 所有 Worker 竞争同一个 `nextIndex`（自增），拉取分片任务
- 每个分片最多重试 3 次（指数退避）

**结果收集 + 有序合并**：
- Worker 把结果放入 `results[index]` 数组（按原始索引）
- `appendPromise` 链式调用保证按序消费：`nextReadyIdx` 从 0 开始，遇到空位则等待
- 避免并发写 Blob 导致分片错乱

**自适应线程调整**（每完成 20 片检查一次）：
- 失败率 > 30% 且线程数 > 5 → 减 5
- 失败率 < 10% 且线程数 < maxCap → 加 10（额外 spawn Worker）

**进度上报**：每 150ms 推送一次，包含百分比、已完成/总数、总字节、实时速度（滑动窗口平均）、ETA

#### 6.4 MP4 / M3U8 原生下载
- MP4 和 m3u8 链接本身用 `GM_download` 提交给浏览器原生下载
- 支持通过 `GM_abort_download` 取消

#### 6.5 任务入口 `TaskRunner`
统一封装流程：
1. M3U8：解析 → 拉密钥（如有）→ 下载分片 → 合并 Blob → 触发下载
2. MP4：直接 `GM_download`
3. 每一步都检查 `cancelCheck`，支持随时中断

### 7. 下载队列管理器 `QueueManager`
- **调度策略**：串行，同时只跑 1 个任务（`maxConcurrent = 1`）
- **去重**：入队前检查 waiting/downloading 中是否存在同 URL + 同参数的任务，重复则拒绝
- **生命周期**：`waiting → downloading → done / error / cancelled`
- 每个任务有独立的 `cancelFlag`，支持单任务取消、全部取消、清理已完成

### 8. UI 层

#### 整体结构
- Shadow DOM 隔离样式
- 固定定位左下角，可收起（`display:none` 切换）
- 三个 Tab：

| Tab | 功能 |
|-----|------|
| 嗅探资源 | 列表展示发现的视频、暂停/继续嗅探、选择后进入配置 |
| 下载配置 | 选择时间范围或分片范围、编辑文件名、加入队列 |
| 下载队列 | 实时进度、状态标签、取消/移除操作 |

#### 嗅探面板
- 每个资源自动触发 `parseM3u8` 解析元信息（时长、分片数、AES 加密标记）
- 异步解析完成后自动刷新 UI

#### 下载配置面板
- M3U8 可选择两种截取模式：**时间区间**（`HHmmss - HHmmss`）或 **分片序号**
- 文件名为点击编辑（textarea，Shift+Enter 换行，Enter 确认）
- 加入队列前收集参数 → 调用 `QueueManager.addTask`

#### 队列面板
- 每个任务对应一个 `UIProxy`，负责该任务行的状态/进度更新
- 通过 Bus 事件驱动：`task-added / task-progress / task-status / task-removed`
- 实时显示：队列总数、下载中数量、等待中数量

### 9. 启动流程

```
Sniffer.start()  →  Hook fetch / XHR / 启动 performance 扫描
      ↓
UI.init()  →  Shadow DOM + 注入样式 + 三个 Tab
      ↓
Bus 事件路由建立
      ↓
等待嗅探资源被发现...
      ↓
用户选择资源 → 配置下载 → 加入队列 → QueueManager 串行调度 TaskRunner
```

## 三、关键设计决策

| 决策 | 原因 |
|------|------|
| 多 Worker 并发但**串行写 Blob** | 避免并发 append 导致 TS 分片顺序错乱 |
| 时间区间下载基于 `timeList` | 不精确到毫秒，但避免用户输入时间超出分片边界 |
| 单任务并发 / 多任务串行 | HTML5 视频同时下载多个会抢占带宽；单任务内部跑满线程效率最高 |
| AES 密钥先批量拉取再解密 | `Promise.all` 并行取 key，避免每个分片单独取 |
| `Bus` 事件总线 | 嗅探器 / 队列 / UI 完全解耦，方便未来扩展 |
